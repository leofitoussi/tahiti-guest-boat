# TGB-55 — missing-page redirects

Verified on 8 November 2026 (Pacific/Tahiti).

Issue: <https://linear.app/tahitiguestboat/issue/TGB-55>

## Cause and fix

The catch-all `/* → /:splat/` rule also matched missing paths that already
ended with a slash. For example, production returned
`/not-a-real-page-seo-audit/ → 301 /not-a-real-page-seo-audit// → 301` to
the same URL indefinitely.

Remove that rule and use Netlify's native Pretty URLs for published directory
indexes. Missing French paths use Astro's `404.html`; the existing `/en/*`
404 rewrite continues to serve the English error page. The webhook rewrite,
legacy Blog redirect and prototype exclusions remain in place.

Netlify documents why slash-only redirect rules loop:
<https://docs.netlify.com/manage/routing/redirects/redirect-options/#trailing-slash>.

## Recheck after publication

```sh
node scripts/check-netlify-routing.mjs https://tahitiguestboat.com /tmp/tgb55-production-routing.json
```

The checker uses GET requests only, discovers published pages from the target
deploy's sitemap, checks each redirect chain and fails on loops, extra hops,
wrong status codes, lost query parameters or wrong error-page language.
It must run against Netlify: Astro preview does not reproduce CDN routing.

Production has not been changed by this preview. Complete TGB-55 only after
merging/publishing and rerunning the HTTP checks against the production domain.
